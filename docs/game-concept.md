# Game Concept: 태생 설계도 — 마음대로 살아낸 생 (가제)

Created: 2026-10-30 · Status: Draft (MVP 구현 시작 — 구현 현황은 저장소 README 참조)

## Elevator Pitch

판타지 세계에 무작위로 태어나 시작 특성을 설계하고, 주사위 판정으로 인생을 헤쳐 가며 3시간(설정 가능) 동안 최대한 많은 돈을 버는 1인용 성인 인생 시뮬레이션 로그라이트 TRPG.

## Core Identity

| Aspect | Detail |
|---|---|
| Genre | 인생 시뮬레이션 + 주사위 TRPG + 로그라이트 런 |
| Platform | Windows PC (단독) |
| Target Audience | 개인 소장용, 성인 전용 (아래 Target Player Profile 참조) |
| Player Count | Single-player |
| Session Length | 목표 3시간(설정 가능), 최고 배속 시 1시간. MVP는 이벤트 약 60개라 실제 약 30~45분으로 예상 |
| Monetization | none (개인 소장) |
| Estimated Scope | Large (MVP 2~4개월 + 이미지 생성 기능, solo; 재산정 필요. 전체 비전은 미산정 — MVP에서 이벤트당 작성 시간을 잰 뒤 산정) |
| Comparable Titles | BitLife, Project Zomboid(특성 선택), 80억 분의 1 (모방 아님; 비교 대상) |

### Core Fantasy

처음부터 끝까지 내가 통제하고, 엄청난 자유도로 마음대로 살아낸 한 생이 하나의 이야기가 된다는 느낌.

### Unique Hook

"BitLife 같은데, 3시간 안에 최대한 돈을 버는 판타지 성인 로그라이트 런이고, 시작 특성 빌드가 인생 전체에 반응한다."

## Player Experience Analysis (MDA Framework)

### Target Aesthetics

| Aesthetic | Priority | How We Deliver It |
|---|---|---|
| Sensation | 6 | 삽화 중심 비주얼 (채색 삽화집 + 운명의 탁상 연출) |
| Fantasy | 3 | 종족, 신분, 마법 소질, 가문 |
| Narrative | 4 | 선택이 만드는 사건 연쇄 |
| Challenge | 2 | 돈 점수 최대화, 3시간 제한 |
| Fellowship | N/A | 1인용 |
| Discovery | 5 | 해금되는 장면, 특성 조합 |
| Expression | 1 | 특성·출생 조합, 진로 선택, 장면 수집 |
| Submission | N/A | 해당 없음 |

### Key Dynamics

- 플레이어가 특성 조합을 실험한다.
- 다음 판을 위해 업적을 노린다.
- 실패 장면도 수집 대상으로 삼는다.
- 모드팩으로 콘텐츠를 직접 만들어 넣는다.

### Core Mechanics

- 출생 변수(종족, 신분, 출생지, 재능·마법 소질, 가문·세력)와 포인트 제한 특성 빌드 (종족 전용 + 공용 특성)
- 상황별 주사위 판정 (주사위 종류와 규칙이 데이터로 정의됨)
- 조건부 이벤트 엔진 (특성·신분·플래그에 반응하는 사건 연쇄)
- 업적 → 특성 포인트 이월, 판을 넘는 장면 갤러리
- 외부 모드팩 로더 (JSON + 이미지, 실행 코드 금지, 로드 시 검증)
- 장면 이미지 자동 생성 (캐릭터 프롬프트 + 장면 태그 → 로컬 생성기로 사전 생성 → 캐시)

## Player Motivation Profile

| Need | How This Game Satisfies It | Strength |
|---|---|---|
| Autonomy | 내가 짠 빌드, 열린 진로 선택, 모드팩으로 콘텐츠 확장 | Core |
| Competence | 돈 점수, 업적, 빌드 최적화 | Core |
| Relatedness | 등장인물과의 관계 사건 | Supporting |

Player Type Appeal (Bartle): Explorers(주) — 특성·출생 조합 실험, 장면 해금 / Achievers(보조) — 업적, 돈 점수, 특성 포인트 이월 / Socializers·Killers 해당 없음 / Bartle 분류 밖의 주 유형: Creators(모드팩 제작)

### Flow State Design

- Onboarding curve: 1~20세 약 20분 튜토리얼에서 주사위와 선택을 익힌다.
- Difficulty scaling: 20세 이후 진로 선택의 위험과 수익이 함께 커진다.
- Feedback clarity: 판정 결과 문장, 수치 변화, 장면 해금으로 즉시 알린다.
- Recovery from failure: 실패 전용 장면과 업적·특성 포인트로 보상한다. 다음 판 재시작이 빠르다. 2회차부터 튜토리얼 압축 또는 건너뛰기 옵션을 검토한다.

## Core Loop

- **Moment-to-Moment (30초)**: 상황 제시 → 판정 방식 선택(상황에 맞는 주사위) → 굴림 → 결과 문장과 수치 변화. 결과가 어떻든 한 장면으로 남는다.
- **Short-Term (5~15분)**: 한 시기(1~2년)를 살며 사건 여러 개를 겪고, 선택의 연쇄가 이어지고, 장면 하나가 해금된다. "한 시기만 더"가 반복 동기다.
- **Session-Level (30~120분)**: 1~20세 튜토리얼(약 20분) → 20세 이후 본 게임 → 최종 돈 결과. 목표 3시간(MVP 콘텐츠로는 약 30~45분 예상), 최고 배속 시 1시간.
- **Long-Term Progression**: 업적 → 특성 포인트 이월 → 다음 판 시작 빌드가 넓어진다. 장면 갤러리를 완성해 간다. 런 점수는 돈 단독이고 장면은 영구 갤러리에 쌓인다.
- **Retention Hooks**: Curiosity(다른 종족·특성 조합, 잠긴 장면), Investment(이월되는 특성 포인트, 갤러리), Mastery(돈 점수 갱신, 빌드 최적화).

## Game Pillars

1. **시작 빌드는 평생 반응한다** — 시작 특성과 출생은 40대의 사건에서도 반응한다. Design test: 범용 이벤트 vs 특성 반응형 이벤트 → 특성 반응형.
2. **주사위는 이야기를 흔든다** — 실패도 하나의 이야기이고, 실패 전용 장면과 업적·특성 포인트 보상이 시간 손해를 일부 상쇄한다. Design test: 성공률 보정 vs 흥미로운 실패 → 흥미로운 실패.
3. **판을 넘어 남는 것은 장면** — 런 점수는 돈 단독이고, 장면은 판을 넘어 영구히 쌓이는 갤러리다. Design test: 이번 판의 돈 vs 영구 수집 → 둘을 분리해서 둘 다 살린다.
4. **한 생애는 짧다** — 3시간 기본값이 정식 경험이고, 시간 설정은 접근성 옵션이다. 선택마다 기회비용이 든다. Design test: 자유로운 탐험 vs 돈 벌기 압박 → 압박. (Pillar 1과 의도적으로 부딪친다.)

### Anti-Pillars

- NOT 전술 전투 게임: 판정 중심 설계가 흐려지기 때문이다.
- NOT 고정 서사를 따라가는 게임: 시작 빌드 반응(Pillar 1)과 충돌하기 때문이다.
- NOT 깊은 연애 시뮬레이션: 범위가 퍼지기 때문이다.
- NOT 하나의 정답 빌드로 굳어지는 게임: 선택의 폭을 해치기 때문이다. 무작위 출생이 주된 완화책이다.

### Content Rules (모드팩 로더가 강제)

- NTR과 "미시" 유형 콘텐츠는 제외한다 (금지 태그로 검증).
- 모드팩에는 실행 코드를 넣지 못한다 (데이터, 이미지, 생성 프롬프트만 허용).

### Image Generation Rules (게임 코드가 강제, 프롬프트 안내로 대체 불가)

- 20세 이전 구간에도 장면 그림은 나온다.
- 가상의 인물만 허용한다. 실존 인물의 성적 이미지는 생성하지 않는다.
- NTR과 "미시" 금지 태그는 생성 요청 단계에서도 거른다.

### 장면 이미지 자동 생성 (사전 생성 + 캐시)

- 사용자가 캐릭터 프롬프트를 모드팩 데이터로 작성한다.
- 그 프롬프트로 기준 이미지를 만들어 얼굴과 체형의 기준으로 삼는다.
- 이벤트는 상황, 장소, 자세를 장면 태그로 가진다.
- 캐릭터를 만든 직후나 판을 시작하기 전에, 필요한 장면을 로컬 생성기로 한꺼번에 생성한다.
- 결과를 캐시에 저장하고 같은 장면은 다시 만들지 않는다. 생성이 덜 된 장면은 기본 이미지로 대체한다.
- 게임은 생성기 없이도 끝까지 플레이할 수 있어야 한다. 모드팩은 고정 이미지와 생성 프롬프트를 모두 가질 수 있다.
- 생성은 로컬에서만 한다.
- 개발 PC 사양: GTX 1660 Ti, RAM 48GB, D 드라이브 여유 521GB. VRAM과 생성 속도는 미측정이다.

### ADR 후보 (테크니컬 디렉터 권고) → `docs/adr/`

- 모드 데이터 형식과 신뢰 경계 (리소스 로더·AssetBundle로 읽지 않음) → ADR-0001
- 이벤트 조건/효과 문법 (닫힌 집합: 비교, 특성 보유, 종족·신분 일치, 플래그, and/or/not) → ADR-0002
- 세이브 형식과 버전 관리 (콘텐츠 ID와 모드팩 버전 기록) → ADR-0003
- 검증 보고서와 "왜 이 이벤트가 안 떴나" 디버그 뷰 → ADR-0004
- (추가) 장면 이미지 생성의 신뢰 경계 → ADR-0005

## Visual Identity Anchor (A+B 조합)

- Direction: 채색 삽화집(Illuminated Storybook) 기반 + 운명의 탁상(Fate Table)의 주사위 연출
- 한 줄 규칙: 모든 화면은 펼친 삽화집이고, 주사위와 카드 연출은 어두운 탁자 위에서 굴러가는 물건으로 처리한다.
- 원칙과 설계 테스트:
  - 일러스트 위에 글자를 직접 얹지 않고 불투명 패널을 쓴다. (글자 가독성 vs 일러스트 노출 → 패널)
  - 주사위 결과는 색뿐 아니라 숫자와 아이콘도 함께 표시한다. (색만 쓸지 vs 병기 → 병기)
  - 장면은 고정 비율 하나로 통일한다. (모드팩 자유도 vs 레이아웃 일관성 → 일관성)
- 색 철학: 종이 바탕(오프화이트, 세피아)에 장면마다 감정을 뜻하는 포인트 색 하나를 둔다 (붉은 계열 열정과 위험, 청록 평온, 금색 성취). 주사위 결과는 대성공 금색, 대실패 짙은 적색.
- 미정: 기본 화풍(반사실, 수채, 애니메풍 등), 인생 단계의 색·조명 구분. /art-bible에서 정한다.
- 스타일 락 문서: 모드팩 제작자용으로 프롬프트 접두사, 비율, 해상도, 팔레트를 정리하고, 모든 인물이 성인임을 명시한다.

## Risks and Open Questions

### Design Risks

- 돈 점수와 특성 포인트 이월 구조가 정답 빌드로 수렴할 수 있다.
- 실패 보상이 시간 손실을 못 메우면 Pillar 2가 조용히 죽는다.
- 2회차부터 1~20세 튜토리얼이 반복 플레이와 충돌한다.

### Technical Risks

- 조건 문법이 점점 스크립트 언어로 변질될 수 있다.
- 모드 변경 후 기존 세이브가 깨질 수 있다.
- 모드 로딩 경로에서 코드 실행 금지 원칙이 구현 중에 조용히 무너질 수 있다 (ADR로 고정 필요).
- GTX 1660 Ti로는 생성이 느리거나 쓸 수 있는 모델이 제한될 수 있다 (미측정). 사양이 부족하면 그래픽카드 업그레이드가 필요할 수 있다.
- 자동 생성은 장면마다 화풍과 얼굴 편차가 커질 수 있다. 공통 프레임, 스타일 락, 기준 이미지로 줄이되 효과는 시험으로 확인해야 한다.

### Scope Risks

- 3시간 플레이를 채우려면 이벤트가 약 150~180개 필요한데 MVP는 약 60개다. MVP에서는 Pillar 4(3시간 압박)와 Pillar 3(갤러리)을 검증하지 못한다. (사용자가 "현 MVP 유지"를 선택함.)
- 기간은 풀타임 기준 2~4개월(낙관 8주, 비관 18주 이상)이고, 신뢰도는 낮다. 이 견적은 이미지 자동 생성 기능을 넣기 전의 값이라 재산정이 필요하다.
- 시작 조합 × 특성 반응에 따른 이벤트 작성량 폭발 위험. 공통 이벤트 안의 조건부 문장·선택지로 처리하는 방식을 이벤트 작성 전에 정해야 한다. → MVP는 이 방식(조건부 문장 조각 `{text, if}`, 조건부 선택지)으로 작성했다.
- 이미지 자동 생성은 스타일 일관성과 사전 생성에 걸리는 시간을 확인해야 한다 (미확인).

- 업적이 특성 포인트로 환산되는 비율은? (MVP 임시값: 업적당 1~2포인트, 누적 상한 +10)
- 진로별 수입 구조와 위험은? (MVP 임시값: `mods/core/data/careers.json`, 시뮬레이터로 조정)
- 사용할 로컬 생성기와 모델, 인물 고정·자세 기법은? (파이프라인 시험으로 확인)
- 한 판에 사전 생성할 장면 수와 걸리는 시간은? (이 PC에서 측정)

## MVP Definition

Core hypothesis: 시작 빌드가 반응하는 주사위 인생 런이 반복해서 하고 싶을 만큼 재미있다.

Required for MVP:

- 종족 3, 신분 2, 출생지 3, 특성 12개(종족 전용 포함), 포인트 제한 특성 선택
- 20세 이후 진로 3개, 상황별 주사위 3종, 이벤트 약 60개
- 장면 약 20종과 이미지 자동 생성(사전 생성 + 캐시), 생성기가 없을 때 쓰는 기본 이미지
- 모드팩 로더 v1 (자체 콘텐츠도 모드팩으로 로드, 검증 포함)
- 저장과 특성 포인트 이월, 배속 UI

Explicitly NOT in MVP: 가문·세력 시스템 / 다수 팩의 로드 순서와 충돌 해결 / 풍부한 업적
