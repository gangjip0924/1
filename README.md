# 태생 설계도 — 마음대로 살아낸 생 (가제)

판타지 세계에 무작위로 태어나 시작 특성을 설계하고, 주사위 판정으로 인생을 헤쳐 가며
제한 시간(기본 3시간) 안에 최대한 많은 돈을 버는 1인용 인생 시뮬레이션 로그라이트 TRPG.
**성인 전용 개인 소장용**입니다.

컨셉 문서: [`docs/game-concept.md`](docs/game-concept.md)

## 실행 (Windows)

1. [Node.js](https://nodejs.org) 18 이상(LTS)을 설치합니다.
2. 이 폴더의 `start.bat`을 더블클릭합니다.
3. 브라우저가 `http://127.0.0.1:41234/`를 엽니다. 창을 닫아도 진행 상황은 자동 저장됩니다.

설치할 패키지는 없습니다(외부 의존성 0). 서버는 이 컴퓨터(127.0.0.1)에서만 열립니다.
세이브·영구 기록·설정·이미지 캐시는 `userdata/` 폴더에 쌓입니다.

```bash
npm start          # 서버 실행 (start.bat과 같음)
npm test           # 엔진·모드 검증·안전 규칙·서버 테스트
npm run validate   # mods/ 폴더의 모드팩 검증 보고서
npm run simulate   # 자동 플레이 1000판으로 밸런스 확인 (node tools/simulate.js 1000 random)
```

## MVP에 들어간 것

| 컨셉 문서의 MVP 항목 | 구현 |
|---|---|
| 종족 3, 신분 2, 출생지 3, 특성 12개(종족 전용 포함), 포인트 제한 특성 선택 | 인간·엘프·드워프 / 평민·귀족 / 벨마르·하젠·아스테라 / 특성 12개(종족 전용 3개, 부정 특성 3개). 운명 다시 굴리기는 특성 포인트를 대가로 최대 3회 |
| 20세 이후 진로 3개, 상황별 주사위 3종, 이벤트 약 60개 | 상인·모험가·마도사(+무직). d20(위험·몸), 2d6(말·흥정, 부분 성공 있음), d100(운·도박). 이벤트 60개 + 공백기용 3개 |
| 장면 약 20종과 이미지 자동 생성(사전 생성 + 캐시), 기본 이미지 | 장면 20개. 로컬 생성기로 판 시작 직후 백그라운드 사전 생성 → 캐시. 생성기가 없으면 기본 삽화(SVG) |
| 모드팩 로더 v1 (자체 콘텐츠도 모드팩, 검증 포함) | `mods/core`도 같은 로더·검증을 거침. 화면 안 "모드팩" 메뉴에 검증 보고서 |
| 저장과 특성 포인트 이월, 배속 UI | 자동 저장·이어하기, 업적 포인트 → 다음 판 특성 포인트(상한 +10), 배속 ×1/×2/×3 |

그 밖에: 디버그 뷰("왜 이 이벤트가 안 떴나", 설정에서 켠 뒤 게임 중 F9), 판을 넘어 쌓이는 장면 갤러리,
실패 전용 장면, 업적 14개, 2회차부터 유년기 압축 옵션, 시간 설정(1~5시간, 무제한은 비공식 기록).

### 시간과 배속

- 화면 오른쪽 위 모래시계가 **게임 시간**입니다. 기본 3시간이 다 흐르면 그 나이에서 생이 끝납니다.
- 배속 ×3이면 모래시계가 세 배로 흘러 실제 1시간이 됩니다(주사위 연출도 빨라짐).
- 메뉴(☰, Esc)를 열거나 창을 내리면 모래시계가 멈춥니다.
- MVP 콘텐츠로는 한 생이 결정 40~50번(약 30~45분)이라 보통 시간보다 수명이 먼저 다합니다.
  3시간 압박(Pillar 4)은 이벤트가 150~180개로 늘어야 검증할 수 있습니다(컨셉 문서의 Scope Risks 참조).

## 장면 이미지 자동 생성 (선택)

생성기가 없어도 게임은 끝까지 할 수 있습니다. 쓰려면:

1. [AUTOMATIC1111 WebUI](https://github.com/AUTOMATIC1111/stable-diffusion-webui) 또는 Forge를 설치하고
   `--api` 옵션으로 실행합니다(기본 주소 `http://127.0.0.1:7860`).
   GTX 1660 Ti(VRAM 6GB)라면 SD 1.5 계열 모델 + `--medvram`부터 시험해 보길 권합니다. 속도는 아직 측정하지 않았습니다.
2. 게임 **설정 → 장면 이미지 생성**에서 "생성 사용"을 켜고 "연결 확인"을 누릅니다.
3. 새 생을 시작하면 오른쪽 위에 `장면 그리는 중 n/20`이 표시되며 유년 → 노년 순으로 미리 그립니다.
   같은 캐릭터·장면·스타일 조합은 캐시(`userdata/cache/`)를 재사용합니다.

- 인물 고정: 캐릭터마다 시드 하나를 모든 장면에 공유합니다. "기준 이미지로 얼굴 고정(실험적)"을 켜면
  기준 초상화를 먼저 만들어 ControlNet(IP-Adapter)으로 성년·노년 장면에 넘깁니다. 실제 생성기로는 아직 시험하지 않았습니다.
- 스타일 락: 접두사·부정 프롬프트·해상도(768×576, 4:3)·샘플러는 `mods/core/data/style.json` 하나로 고정됩니다.

### 게임 코드가 강제하는 규칙

모드팩 데이터나 설정으로 끌 수 없습니다(`src/shared/safety.js`, `src/shared/validate.js`).

- 프롬프트는 **서버가** 모드 데이터로 직접 조립하고 다시 검사합니다. 브라우저가 보낸 문장을 그대로 생성기에 넘기지 않습니다.
- 20세 미만 단계(유년·소년기) 장면: 일반 등급만, 자유 서술 외형 제외, 성적·노출 표현이 있으면 생성 거부, 안전 부정 프롬프트 강제.
- 등장인물(NPC)은 가상 인물(`fictional: true`)이며 20세 이상이어야 합니다. 실존 인물 표지 단어와 차단 목록(`mods/core/data/blocklist.json`)에 걸리면 거부합니다.
  실존 인물 이름 목록은 완전할 수 없으므로, 필요한 이름은 차단 목록에 직접 추가하세요.
- NTR·"미시" 유형 금지 태그는 모드 로드 단계와 생성 요청 단계 양쪽에서 거릅니다.
- 성인 등급 장면은 설정에서 켜야 하고, 성년·노년 단계 장면에만 허용됩니다. 기본 콘텐츠에는 성인 등급 장면이 없습니다.
- 생성기 주소는 이 컴퓨터(127.0.0.1/localhost)만 허용합니다.

## 모드팩

`mods/<팩 ID>/manifest.json` + `data/*.json` + `images/*`. JSON·이미지만 넣을 수 있고, 다른 확장자 파일이
하나라도 있으면 팩 전체를 거부합니다. 형식은 [`docs/modding.md`](docs/modding.md)를 보세요.
`mods/core`가 그대로 예제입니다.

## 구조

```
server.js              로컬 서버: 정적 파일, 모드 제공, 저장, 이미지 생성 프록시·캐시
src/shared/            브라우저와 Node가 함께 쓰는 엔진 (외부 의존성 없음)
  conditions.js        닫힌 조건 문법        effects.js   닫힌 효과 문법
  dice.js              데이터 정의 주사위     engine.js    한 생의 진행 규칙
  validate.js          모드팩 검증           modloader.js 모드팩 로더 v1
  safety.js            콘텐츠·이미지 생성 규칙  prompt.js    장면 프롬프트 조립
  save.js              세이브·영구 기록
public/                화면 (HTML/CSS/JS 모듈, 빌드 단계 없음)
mods/core/             기본 콘텐츠 모드팩
tools/                 검증 보고서, 자동 플레이 시뮬레이터
tests/                 node:test 테스트
docs/                  컨셉 문서, ADR, 모딩 가이드
```

엔진 선택과 설계 결정은 [`docs/adr/`](docs/adr/)에 있습니다.

## 아직 안 된 것 / 다음 단계

- 단독 실행 파일(.exe) 패키징: 지금은 Node + 브라우저로 실행합니다. Electron/Tauri로 감싸는 것은 ADR-0001의 후속 과제입니다.
- 실제 생성기(1660 Ti)에서의 속도·화풍 일관성·인물 고정 시험(컨셉 문서 Next Steps의 "이미지 파이프라인 시험").
- 아트 바이블(기본 화풍, 인생 단계별 색·조명), 진로별 밸런스 플레이테스트.
- MVP 범위 밖: 가문·세력, 다수 팩의 로드 순서·충돌 해결(지금은 ID가 겹치면 뒤 팩을 거부), 풍부한 업적.
